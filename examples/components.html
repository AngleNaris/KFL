01 · Foundation

Typography

One family, a handful of roles. Hierarchy comes from size steps of at least 1.25×, then weight, then space; color is the last lever, not the first. Line heights land on a 4px rhythm, and Chinese, Japanese or Korean text gets more leading automatically.

Rules

  • Reading text is 16px or larger.
  • Floors: 10px Latin, 12px CJK — limits, not targets.
  • Tabular figures wherever numbers line up.
  • Negative tracking only at display sizes; none for CJK.

02 · Foundation

Color

Neutral surfaces carry the page. One accent means “interactive state” — links, focus, selection, progress — and the primary action is ink, so the two never compete. State colors appear only for states that really exist, and always with words and an icon.

Contrast

Ratios below are measured live against the surface in the current theme. Text needs 4.5:1, control edges 3:1.

Adapting

Change tokens, not components. Point --kfl-action at the accent for a brand-colored primary.

03 · Foundation

Icons

One drawing contract: a 24px grid, 2px stroke, square caps and miter joins — a round cap would turn every stroke into a pill. Icons support a label and rarely replace one. Icon-only controls are for the universal few (close, search, menu, more) and still carry an accessible name and a tooltip.

Never

Emoji, letters, punctuation or Unicode symbols standing in for icons.

Markup

<span class="kfl-icon" data-icon="check" aria-hidden="true">

    04 · Action

    Button

    Buttons act; links go somewhere. One primary button per view or region marks the next step, and everything else steps down to secondary or quiet. Labels are verbs that name the result — “Save changes”, “Export CSV” — never “OK” or “Submit”.

    Keyboard

    Enter or Space activates.

    States

    • Hover, a 1px press, a focus ring.
    • Disabled says why, nearby.
    • Busy keeps its size and blocks repeats.

    Sizes

    32, 40, 48px — all 44px on touch screens.

    Variants — primary, secondary, quiet, danger, danger secondary

    Sizes — sm, md, lg

    With icons — a leading icon names the kind of action, a trailing arrow means “onward”

    Disabled, with its reason · Busy (demo: simulates a 1.5 s request, nothing is sent)

    Add a title to publish.

    05 · Action

    Link

    Links navigate. In running text they are underlined and accent-colored, because that is what people look for. A standalone link adds an arrow when it leads onward; a link that leaves the product says so with the external icon.

    Avoid

    • “Click here” — the link text names the destination.
    • Opening new tabs by default; people choose that.

    06 · Input

    Text field

    Label, hint, control, error — in that order. The label is always visible; a placeholder only shows an example format. Size a field to its expected answer, and mark the optional minority instead of starring the required majority. Use the right type, inputmode and autocomplete so phones show the right keyboard and browsers can fill it in.

    Validation

    Nothing is judged while someone types. Errors appear on submit and clear the moment the value is valid.

    Tokens

    --kfl-line edge (3:1), --kfl-focus ring, 16px text so phones do not zoom.

    07 · Input

    Checkbox, radio

    A square box means “any number”; a circle means “exactly one”. That shape difference is a convention people rely on, which is why the radio is the kit's one sanctioned curve. Group related options in a fieldset with a legend; past about seven radio options, use a select.

    Keyboard

    Space toggles a checkbox. In a radio group, arrow keys move and select.

    Target

    The whole row is the target: 24px, and 44px on touch.

    08 · Input

    Switch

    A switch changes a setting the moment it moves — there is no save button behind it. If the change waits for a form to be submitted, use a checkbox instead. The label names the setting, not the action.

    Keyboard

    Space toggles.

    Markup

    <input type="checkbox" role="switch"> — native, labelled, announced as on or off.

    09 · Input

    Segmented control

    Switches between a few views of the same content, in place: two to five short options, one always selected. It is a radio group underneath, so it inherits native keyboard behavior and semantics.

    Keyboard

    Tab enters at the selected option; arrow keys move and select.

    16 · Data

    Table

    For comparing across rows. Numbers align to the end in tabular figures so digits line up; text aligns to the start; the table's first and last columns sit on the region's edges. On a narrow screen the wrapper scrolls sideways, never the page.

    Keyboard

    Sortable headers are buttons. The scroll region is focusable, so arrow keys can scroll it.

    Selection

    The header checkbox selects every row and turns indeterminate for a partial selection; bulk actions appear only while something is selected.

    Alert

    Inline and persistent, for conditions someone must notice or act on: a failed action, a limit reached, a change that affects this page. Place it next to what it is about, and give it a way forward.

    26 · Feedback

    Tooltip

    The visible name of an icon-only control, in the same words as its accessible name. It appears after a short delay on hover and at once on keyboard focus, stays while the pointer moves onto it, and hides with Escape. Never the only place for information someone needs.

    27 · Overlay

    Dialog

    A short, blocking decision that must be answered before going on. Name the object and the consequence, and label the confirming button with the action itself. Anything longer than a few fields gets a page, not a dialog, and dialogs never stack.

    Keyboard

    Focus moves in — to the safe choice when the action cannot be undone. Tab stays inside; Escape cancels; focus returns to the trigger.

    Dismissal

    A backdrop click closes only dialogs that hold no input.

    29 · Overlay

    Menu

    Actions on one object, behind a button when there are too many to show. Keep frequent actions in view and let the menu hold the rest; destructive items go last, after a separator. It opens from its trigger and collapses back toward it.

    Keyboard

    Enter, Space or Down opens it on the first item; arrows move; typing a letter jumps; Escape closes and returns focus to the button.

    30 · Disclosure

    Disclosure

    Progressive disclosure for secondary detail — answers, advanced options. The summaries stay visible, so people can scan before opening. Give several the same name to keep one open at a time.

    Can I change the billing cycle later?

    Yes. A switch to yearly billing starts on the day you make it; the unused part of the current month is credited.

    Who can see invoices?

    Owners and accountants. Members see only the invoices of projects they belong to.

    What happens to deleted invoices?

    They move to Archived for 30 days and can be restored from there.

    31 · Composition

    Form

    One column, in the order people think about the answers. Nothing is judged while someone types. On submit, every problem is listed at the top and marked at its field, every value stays, and each error clears the moment it is fixed. Try submitting it empty.

    Actions

    After the last field, on its start edge, primary first — where the eye finishes the form.
